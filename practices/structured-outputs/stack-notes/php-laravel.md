# Stack-notes — PHP / Laravel

Written 2026-10-01 from the contract; no field report yet. Native structured outputs are a **provider** feature: PHP gets the same guarantee by sending the JSON Schema in the request body — the differences are the schema generator, the validation idiom and the runtime model. Check package versions at adoption.

- **Schema generator:** there is no Pydantic; write the JSON Schema by hand (a PHP array), or generate it from a typed DTO with a schema package, and keep it in a versioned file next to the prompt (assertion 10). Hand-written schemas are where `additionalProperties: false` and the full `required` list get forgotten — make the checklist in `schema-design-rules.md` a test that walks every schema file.
- **Package family:** the same choice as `../../llm-api-calls/stack-notes/php-laravel.md` — the official `anthropic-ai/sdk` (https://packagist.org/packages/anthropic-ai/sdk) or `openai-php/client` (https://packagist.org/packages/openai-php/client), or the Laravel-native Prism (`prism-php/prism`, https://packagist.org/packages/prism-php/prism), which has a structured-output mode; one class instantiates it. For checking schemas in tests: `opis/json-schema` (https://packagist.org/packages/opis/json-schema) or `justinrainbow/json-schema` (https://packagist.org/packages/justinrainbow/json-schema) — both on Packagist as of 2026-10-01.
- **Native mode:** with the vendor SDK or the HTTP client, send `output_config.format` (Anthropic) / the strict `text.format` (OpenAI) as read on 2026-10-01; parse with `json_decode(..., associative, flags: JSON_THROW_ON_ERROR)` only *after* checking the stop reason — refusal and truncation are branches, not exceptions (assertion 5).
- **Validation idiom:** the contract allows exceptions; the Laravel-native form is a Form Request or a `Validator::make` with custom rules for the invariants (totals add up, ids exist, quotes in the source), and the *message* of the failed rule is the re-ask prompt (assertion 3). The JSON-Schema validator package checks shape in tests (and the `additionalProperties`/`required` checklist); in production the provider already guarantees it.
- **Re-ask ownership:** implement the one bounded re-ask in the client service class (the one place that calls the vendor), with the attempt count in the usage log; no second layer — Laravel AI packages that "retry until valid" must have that retry set to zero (assertion 4).
- **Result shape:** a small `StructuredResult` value object with `branch`, `value`, `message`, `attempts`, `schemaVersion` keeps the four branches explicit; or throw typed exceptions (`RefusedException`, `TruncatedException`, `InvalidOutputException`) and catch them at the handler — either satisfies the contract.
- **Streaming partial objects:** PHP has no incremental JSON parser in the standard library; prefer *iterable* mode (one complete object per SSE event) or non-streamed structured calls; a streamed declarative UI spec is a queued job with polling (`../llm-api-calls/stack-notes/php-laravel.md`).
- **Classifier tier:** PHP-FPM is request-scoped, so a self-hosted encoder is an HTTP sidecar (a small Python service) called with a timeout and the fail-open/closed policy from `guardrail-policy.md`; a hosted moderation endpoint is one HTTP call. Never load a model in the PHP process.
- **Logprobs:** depends on the provider's API, not on PHP; record the choice in the decision file.
- **Generative UI:** Blade or Inertia components keyed by a `type` field over the declarative spec, with a `match` expression and no default branch that renders; `{!! !!}` (unescaped output) on model data is the anti-pattern to grep for.
- **Guardrail fixture:** a Pest or PHPUnit data provider over the YAML items, run in the same CI job as the smoke test, with the vendor client faked.

# Stack-notes — Python (the reference stack)

Written 2026-10-01. The reference `structured_call.py` targets the official `anthropic` SDK (https://github.com/anthropics/anthropic-sdk-python) with Pydantic (https://docs.pydantic.dev/); the `openai` SDK (https://github.com/openai/openai-python) has the same shape (`responses.parse`, `text_format`, `output_parsed`). Check current versions at adoption.

- **Schema generator:** Pydantic models with `ConfigDict(extra="forbid")` give `additionalProperties: false`; a field *with a default* is dropped from `required` — give optionals no default and the type `X | None` (assertion 2).
- **SDK native mode:** `client.messages.parse(output_format=Model)` transforms the schema, validates and returns `parsed_output` — but it validates *inside* the call, so the reference uses `messages.create` with `output_config={"format": {"type": "json_schema", "schema": …}}`, checks `stop_reason` first and runs `Model.model_validate_json` itself; a `ValidationError` there is the re-ask trigger. `create` sends the schema untransformed: `extra="forbid"` on every model, no `minimum`/`maximum`/length constraints, and a `pattern` is a hint the API accepts but the SDK helper (`transform_schema`, 1.11.0) would strip — validate it in code.
- **Terminations:** `stop_reason == "refusal"` and `stop_reason == "max_tokens"` are branches in `structured_call.py`; they never reach `json.loads`.
- **Re-ask ownership:** Instructor (https://python.useinstructor.com/, `max_retries`) and Pydantic AI (https://ai.pydantic.dev/, `retries`) both re-ask on validation failure. Use *one* of them *or* the reference module, never two; on a provider with native constrained decoding set a library's schema-level retries to zero (assertion 4). Instructor's `partial` / `iterable` modes are the streaming helpers when a route streams objects.
- **Pydantic AI** fits when the feature is an agent (system prompt + tools + a typed return type); its `TestModel` / `FunctionModel` are the mock-model mechanism for unit tests without a provider call.
- **Strict tools:** `strict=True` in the tool dict with `input_schema` from `Model.model_json_schema()`; the same 20 / 24 / 16 limits apply across all strict schemas in a request (dated 2026-10-01).
- **Logprobs:** the Anthropic Messages API reference shows no logprobs field, as far as checked on 2026-10-01; the OpenAI Chat Completions API exposes `logprobs` / `top_logprobs` — the decision file records which the chosen model supports (`decision-vs-generation.md` rule 3).
- **Classifier tier:** a self-hosted encoder (the ModernBERT recipe) runs as a separate HTTP sidecar (its own process, `transformers` — https://github.com/huggingface/transformers — and a small server), never imported into the web worker; a hosted moderation endpoint is one call from the client module.
- **Async:** both SDKs have async clients; `messages.parse` has the same async form; a FastAPI handler must use it or offload to a thread.
- **Pitfall:** `model_json_schema()` emits `$defs` for nested models — both providers accept them; `title` keys are noise the provider ignores. A `Literal` enum is emitted as `enum`; add the out value there, not as a comment.
- **Pitfall:** `Generic[T]` Pydantic models (the `Maybe[T]` shape) must be parametrised (`Maybe[User]`) before their schema is emitted.
- **One client:** the module imports `client()` from the `llm-api-calls` client module (`llm.py`); it never calls `anthropic.Anthropic(...)` itself.

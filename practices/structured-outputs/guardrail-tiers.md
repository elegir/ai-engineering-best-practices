# Guardrail tiers — rules and grounding, then a classifier, then a judge; and where each runs for a solo operator

Read; the choice per guardrail goes into the *tier* column of `guardrail-policy.md`. Principle: `../../principles/13-structured-outputs-and-guardrails.md` §3.3. Sources: Shreya Rajpal (AI Engineer, 2023-11); Diego Carpintero, *$1 AI Guardrails: the unreasonable effectiveness of fine-tuned ModernBERT* (AI Engineer, 2026-04 — raw file `…caravana…`); OpenAI Agents SDK guardrails page, Guardrails AI README and NeMo Guardrails overview (read 2026-10-01); Sam Witteveen and Boundary on Jev (2026-09) — digest `../../sources/2026-10-01-s04-structured-outputs-digest.md` §3.3–3.4. All numbers below are the speakers' own measurements, as stated.

## The ordering, and why

Rajpal's order, which Carpintero's whole talk confirms: cheap and deterministic first, expensive and probabilistic last. The reason is not only cost. Prompting "doesn't act as a guarantee" (the same evaluator prompt at temperature 0 gave different numbers across five identical runs — Rajpal); an LLM judging an LLM shares its blind spots (`../../principles/10-llm-api-fundamentals.md` §3.1); and a judge in the request path "can easily compound into… seconds of latency" (Carpintero). So each tier is tried before the next, and a check moves up a tier only when the fixture (`guardrail-fixture.md`) shows the lower tier misses cases.

| Tier | What it is | Examples from the sources | Latency / cost (speaker's figures) | Catches | Misses |
|---|---|---|---|---|---|
| **0 — Ground in an external system** | Execute or look up the output against the real thing | text-to-SQL run against a sandbox with the real schema "substantially improved the correctness" (Rajpal); every URL returns 200, every id exists (Liu); the quote is a substring of the source | one query / one request | anything the system of record can refute | what the system cannot see (tone, intent) |
| **1 — Rules and heuristics** | Schema validators, regex, allow-lists, size caps, tenant ACLs | an interest rate ends with `%`; a regex for "ignore previous instructions" (Rajpal); tool allow-list with per-agent, per-day, per-amount, per-tenant limits (Bhardwaj); strip markup and cap size on fetched content | microseconds; free | the known shapes of a known attack or error | paraphrases, encodings, novel attacks — a rule is a first layer, not a control |
| **2 — Small discriminative classifier** | An encoder or a hosted moderation endpoint returning a probability per class | Carpintero's recipe: ModernBERT fine-tuned on **Inject Guard** (75k labelled prompts from 20 open sources) — "almost 85 % accuracy using only 35 milliseconds per classification" on unseen benchmarks, the ~150 M base vs the large model "almost six points" apart, under a dollar of compute, **self-hosted**, **retrainable in hours** as attacks mutate; a safety check "is fairly regarded as a discrimination or a classification problem" | 35–40 ms per check (Carpintero); a hosted moderation endpoint is one HTTP call | the recurring risk classes: injection, PII, toxicity, off-topic, competitor mentions, language, sentiment | reasoning about context ("is this *allowed* for this user?"); anything with few training examples |
| **2b — Probability-returning decision model** | A hosted model that answers typed questions (choice / score / yes-no) with calibrated probabilities in one forward pass | Jev (Type-Safe AI, 2026-09): Witteveen's demo classifies language, sentiment, routing, PII, spam, injection attempts and sarcasm in 70–500 ms, with free output tokens; still stochastic; cannot produce arguments; "cannot hallucinate" means only that it stays inside the option set | 70–500 ms round trip (Witteveen) | the same classes as tier 2 without training a model | a dated product with no paper and no architecture disclosure — re-evaluate after 2026-12 with a 20-case eval against the cheapest chat model (digest §4, §7.6) |
| **3 — LLM judge / self-reflection** | A generative model asked whether the input or output violates a policy | the Agents SDK's own example is a small agent returning `is_math_homework` — chosen for developer convenience; NeMo's "LLM self-checking" rails; Rajpal's provenance self-reflection | hundreds of ms to seconds; tokens per check; "run a guardrail with a fast/cheap model… saving time and money" (Agents SDK) | "squishy" judgements: tone, policy nuance, intent | calibration and consistency (`decision-vs-generation.md`); correlated failures — never the sole gate on anything irreversible |

## Where each tier runs — for a solo operator (opinion, stated as such)

Carpintero argues for self-hosting the classifier (privacy — "no intermediate steps sent to a third party" —, cost, retrain cadence); Jev and the Guardrails Hub are hosted; Guardrails AI is *discontinuing* hosted inference (README, 2026-07-06 item, cut-off 2026-08-25). For Martin's products the KB's position is:

1. **Day zero: tiers 0 and 1** in the product's own code — validators (`structured_call.py`), allow-lists, size caps, tenant scoping. No extra process.
2. **First user: tier 2 hosted** — the provider's moderation endpoint or a hosted classification service — because it is one HTTP call with no model to operate, and the fixture tells you what it misses.
3. **At scale, or when the data must not leave your infrastructure (`personal_data`, `regulated`): tier 2 self-hosted** — Carpintero's recipe. It is a **separate process** in every stack: an HTTP sidecar next to the application, never loaded in-process (a request-scoped runtime such as PHP-FPM cannot hold a model; a Python web worker should not either — `stack-notes/`). Budget the retrain: attacks mutate, "in hours" is the claim, the fixture is the regression test.
4. **Tier 3 only where the policy is squishy and the route is not time-critical**, and never alone on a side-effect path (`guardrail-policy.md` rule 6).

## Threat vectors a classifier is trained against (Carpintero's survey; depth parked for session 14)

Direct injection (natural-language instructions in the user turn); indirect injection (instructions in fetched pages, documents, tool results — the 2026-03 ad-review case); adversarial suffixes found on open weights that transfer to closed models; RAG poisoning; the MCP tool-description asymmetry (the human approves a one-line summary, the model reads the full description — review the full description, `../security-baseline/mcp-trust-register.md`); agentic chains (a page that tells a computer-use agent to download a file; an issue title interpolated into a coding agent's prompt). Rows for each are in `../security-baseline/threat-model-agentic.md`. The structural cause — "LLMs have no native separation of concerns between the system controls and the data" — is why a tier is a layer and the trust boundary stays in code.

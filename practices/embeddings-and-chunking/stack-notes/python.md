# Stack-notes — Python (the reference stack)

Written 2026-10-04 from the contract; no field report yet. The reference `embedding_config_and_chunker.py` needs only the standard library; the real tokenizer, the provider call and the store are wired behind its three seams (`<<TOKENIZER>>`, `<<EMBED_BACKEND>>`, `InMemoryIndex`). Check current versions and licences at adoption.

- **Tokenizer:** tiktoken (https://github.com/openai/tiktoken) with `cl100k_base` for OpenAI's third-generation embedding models (OpenAI guide, read 2026-10-04); the provider's own tokenizer or the Hugging Face tokenizer of an open model otherwise. Implement `encode()` returning character spans (`encode_with_offsets` or `offset_mapping`) so the harness keeps its token-level metrics; put the tokenizer's name in `EmbeddingConfig.tokenizer_name` so a tokenizer change is a configuration change.
- **Provider call:** the repo's one LLM client (`../../llm-api-calls/`) with the provider's embeddings endpoint; pass `input_type` (Voyage, Cohere) or ignore it (OpenAI) inside the backend — callers only pass `side`. Batch document embedding behind the client's retry and rate-limit handling; a failed batch never writes a partial index.
- **Splitters behind the `Chunker` protocol:** LangChain's `RecursiveCharacterTextSplitter.from_tiktoken_encoder` or chonkie (https://github.com/chonkie-inc/chonkie) for recursive and semantic variants; keep the reference's `_enforce_limit()` in front of any library so an oversize chunk is refused before it reaches the embedder, and keep `record()` so the manifest names the library and its parameters.
- **Structure-aware option:** Docling's `HybridChunker` (https://github.com/docling-project/docling) with the model's tokenizer — "it works with your specific tokenizer" (Ebbelaar 2025-02) — or Unstructured's `chunk_by_title` with tables standalone; map their output to `Chunk` and run `check_structure()` on it, because the library's defaults may merge a title or split a table.
- **Store:** pgvector (https://github.com/pgvector/pgvector) with the column `vector(<<DIMENSIONS>>)` fixed by the migration — the dimension refusal for free — and one table per fingerprint (`index_<fingerprint>`); the manifest as a row in a small `index_manifests` table read at startup; LanceDB (https://lancedb.github.io/lancedb/) for local or single-tenant products with the manifest as a JSON file beside the table.
- **Eval set generation:** `make_eval_set()` wired to the same LLM client with Chroma's prompt shape, the exact-match filter and a cosine near-duplicate filter; run once per corpus and on demand, never in CI.
- **CI gate:** `--check` as a pre-merge job and a pre-commit hook on paths `src/<package>/retrieval/**`, `evals/retrieval/**` and the stack document; the stub embedder keeps it keyless and deterministic.
- **Tests:** `tests/test_retrieval_config.py` re-runs the demo's refusals against the real tokenizer and store: unpinned config, side missing, oversize chunk, split table, build without eval, foreign-fingerprint upsert.
- **Pitfall:** approximate token counts near the model's maximum — the reference's `ApproxTokenizer` is declared approximate; with the real tokenizer wired, keep a safety margin only if the provider truncates silently.
- **Pitfall:** a provider SDK that normalises or truncates vectors on its own — check the returned length against `dimensions` (the reference does) rather than trusting the parameter.

# Stack-notes — Python (the reference stack)

Written 2026-10-01. The reference `memory_store.py` needs the standard library and Pydantic (https://docs.pydantic.dev/) for the typed consolidation decision; the extraction and consolidation calls go through the repo's one client module (`../../llm-api-calls/`) as structured calls (`../../structured-outputs/structured_call.py`). Check current versions at adoption.

- **Store:** replace `InMemoryStore` with a table (`owner`, `type`, `text`, `status`, `importance`, `source`, timestamps, `trail` as JSON) behind the same five methods; SQLAlchemy (https://www.sqlalchemy.org/) or the repo's ORM; `for_owner()` is a `WHERE owner = :identity` and nothing in the module queries without it.
- **Neighbours:** token overlap on day one; `pgvector` (https://github.com/pgvector/pgvector) or the repo's vector store when a per-owner store grows — the similarity query carries the owner filter as a metadata filter, never as a post-hoc check.
- **Off the response path:** a FastAPI `BackgroundTask`, Celery (https://docs.celeryq.dev/) or an `asyncio.create_task` after the reply is streamed; `remember()` is the job body; the reply handler never awaits it.
- **Consolidation model:** a reasoning-capable tier from `../../../principles/08-model-selection.md`; Mem0's finding (a small *reasoning* model over a small *chat* model for the update decision) is the reason this is not the cheapest route.
- **Framework stores:** LangGraph's `Store` (https://docs.langchain.com/oss/python/concepts/memory — namespaces, JSON documents, filter + similarity search; `InMemoryStore` for tests) fits the substrate role; Mem0 OSS (https://github.com/mem0ai/mem0) implements extract → consolidate with `add`/`search`, `infer=False` for bulk import, and per-use-case include/exclude prompts; LangMem (https://langchain-ai.github.io/langmem/) is parked for the s5 validation pass. Whichever is used, assertions 1–7 are checked against it, not assumed from its README.
- **Anthropic's memory tool:** the Python SDK has a helper that dispatches `view` / `create` / `str_replace` / `insert` / `delete` / `rename` to a handler class you write; implement the handler over the same store with the duties of `memory-tool-handler-notes.md` (path validation first).
- **Identity:** a `Identity` value object (tenant, user) passed explicitly; `search(store, identity, …)` has no default for `identity`; a test with two identities and overlapping facts lives in `tests/test_memory.py` (assertion 3).
- **Secrets:** `SECRET_SHAPES` are a start; `detect-secrets` (https://github.com/Yelp/detect-secrets) patterns can be reused in `_passes_exclusions()`; the check runs at extraction, before consolidation.
- **Erasure:** `erase()` deletes the row and the vector entry in one transaction and writes the request reference to the application's audit log, never the content.
- **Pitfall:** `datetime.now()` inside `score()` makes the memory eval non-reproducible — inject the clock (the reference's `now` argument) and advance it between simulated sessions.
- **Pitfall:** a consolidator returning free text instead of the `{reasoning, action, target, new_text}` object — route it through the structured call so the schema is guaranteed; the reference defaults to NOOP on a parse failure so nothing is appended by accident.

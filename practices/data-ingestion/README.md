# Data ingestion

## Solves
The product retrieves over documents or data and one of these symptoms appears: an answer cites a page that does not exist, or a chunk nobody can trace back to a file; a table was answered wrong because it reached the model as whitespace-separated prose; one document is indexed three times (three paths, three content hashes, three different answers); a phone number, an email or an API key shows up in a reply because it was embedded before anyone looked; a customer's document surfaces in another customer's conversation; an erasure request deletes the row and leaves the embedding, the cached answer and the eval case; nobody can say how many documents the corpus holds, how old they are or who owns them; the parser was chosen on five sample PDFs and the long tail of scans, forms and merged-cell tables fails silently in production.

## Applies when
- The fact `retrieval` holds (`../facts.md`): the product fetches documents or rows into the window. Everything that reaches the index passes through this folder's path — audit → parse → scrub → envelope → upsert — and everything that leaves it passes through `tombstone()` or `erase_subject()`.
- The **full** part (assertions 6–8: the PII scrub, the erasure path, tenant isolation as an RLS policy where the store is Postgres) attaches when `personal_data or regulated or multi_tenant` also holds — the safety facts of `../security-baseline/`, because the scrub, the anonymity test, the erasure path and the tenant tag are the controls those facts demand.
- Extraction without retrieval (a pipeline that reads documents into structured records and never indexes them) is covered by `llm_calls` plus this README read for the parser adapter and the audit report; it does not route here.

## Does not apply when
- The knowledge is **in the window** — a bounded, stable corpus put in the cached prefix (`../context-management/context-store-decision.md`, long context or cached corpus). No index, no envelope; the audit report is still worth running once.
- The corpus is **code or documentation for a coding agent** — agentic search (`../agent-patterns/agentic-rag-skeleton.py`) over files that already have names and structure; no parsing.
- **Chunking and embeddings** (size, overlap, by-title, contextual chunking, the embedding configuration) — `../embeddings-and-chunking/` (s7, 2026-10-04); **retrieval quality** (hybrid search, reranking, query rewriting) — sessions 9–11; **memory** of what the product learned about a user — `../memory-and-permissions/`. Those folders read the envelope this one writes.
- Runtime guardrails on user input and model output are `../structured-outputs/guardrail-policy.md` (G1, G3); this folder is the **G0 ingestion checkpoint** — what must never enter the index.

## Reference implementation

`ingestion_pipeline.py`: one module implementing assertions 1, 2, 3, 5, 6, 7 and 8 for Python with an in-memory store, the real parser left as an adapter (`Parser.parse()` returning `Element`s) and `--demo` standing in for it with a line-based `FakeParser`. The mechanism it fixes is the path: a corpus is audited (`audit_report`), each document is parsed into typed elements with page and bounding box, each element is scrubbed (`pii_scrub` — mask with a placeholder the `ReversibleDictionary` can undo, or quarantine with a reason), wrapped in an `Envelope` whose owner comes from the manifest through `tag_owner(doc, ingestion_identity)` (no owner → the document is refused) and whose tenant is always the ingestion identity's, and upserted by document hash (`ingest_document`: a previous hash equal to the current one is a `noop`, a different one a `replace`, none an `insert`; `sync_corpus` first refuses to run without a current audit report, then tombstones what the corpus no longer holds, within the job's tenant). Reads apply the tenant predicate before ranking (`InMemoryStore.search`); `erase_subject` removes a subject from the index, the answer cache, the eval set and the log and returns when it happened against the policy deadline; `mentions()` (by tag) and `scan_content()` (by content) are the two proofs — the demo shows why both are needed. **Python idioms, not required** (decision 0005 §3): pydantic models, the dict store, the line-based fake parser, token overlap as similarity, Luhn in Python. Any stack satisfies the contract with a report file regenerated per parser version, a table of elements with the envelope columns and a non-null owner and tenant, a scrub step before the insert, an upsert keyed on `(tenant, source_id, document_hash)`, a tenant predicate the ORM cannot drop (an RLS policy on Postgres), and a deletion job that touches four stores and asserts zero. Other stacks: `stack-notes/<stack>.md` and, once a real repo passes Verify, `variants/<stack>/`.

## Stack-sensitive points

- **Parsing is CPU-bound and slow**: a queue in a request-scoped runtime (a job per document), a worker pool in a long-lived one; never inside the request that uploaded the file.
- **The tenant is the ingestion identity's, full stop**: the job carries the tenant, the manifest carries the owner, and `tag_owner()` refuses a document with no owner or with a manifest tenant that differs from the job's — there is no argument on the ingestion path that moves a document into another tenant, and tombstones stay inside the job's tenant.
- **RLS exists only on Postgres**; elsewhere the store's native partition (a namespace, a collection per tenant) plus the mandatory filter of `../memory-and-permissions/permission-model.md` §3 is the enforcement point, and the two-identity test is what proves it.
- **The reversible dictionary is a secret under the tenant scope**, not a column beside the embeddings: a leak of the index must leak placeholders, not values.
- **Idempotent upsert needs a stable document identity** — path plus content hash; a store that generates ids on insert will grow on every run.
- **Erasure reaches four places that live in different systems** (vector store, answer cache, eval datastore, log pipeline); the deletion test runs against all four, not the one that is convenient.

## Verify

Each numbered line is a stack-neutral assertion — the contract (decision 0005 §2). `observer` says who judges it: `script` (a command's exit code), `agent` (observed in a session), `Martin` (a human reads it). `negative` is what must make it fail. `framework: beats` means the assertion wins over the repo's library; `bends` means the library's convention may stand. Stack-specific commands live only under *Example commands (Python)*. Assertions 6–8 belong to the full part.

1. An audit report exists for every corpus and is regenerated on every parser, source or policy change: counts by type, duplicates, empty or garbled pages, PII hits, date coverage, sources with no owner — observer: script — negative: an index built from a corpus with no report, or a report older than the parser version in use
2. Every indexed element carries an envelope with source id, filename, page, element type, content hash, owner and tenant, sensitivity, ingested-at, parser version and document date; its filename, title, page and date are rendered as a metadata prefix into the chunk text by the chunker (Jason Liu's blog, 2024-05-11; `../embeddings-and-chunking/`, enforced there — owner and tenant are never embedded) — observer: script — negative: an element with no page or no owner, or (in that folder) a chunk without the prefix
3. Tables are kept as table elements with a structured view (HTML or lossless JSON) and a separate text rendering for the embedding model — observer: agent — negative: a merged-cell table reaching the model as whitespace-separated prose
4. The parser was chosen on at least one thousand of the product's own pages with an automated comparison, and its output is tracked on a production sample — observer: Martin — negative: a parser chosen on fewer than one thousand pages, or no production sample — framework: bends
5. Re-ingesting an unchanged corpus produces zero new elements and zero duplicates; a changed document replaces its elements; a removed document is tombstoned — observer: script — negative: a second run that grows the index
6. (full) No element containing a configured PII class or a secret-shaped string enters the index: it is scrubbed, or quarantined with a reason; the test plants one of each class — observer: script — negative: the planted string retrievable
7. (full) An erasure request removes a subject's documents from the index, the caches, the eval datasets, the logs and every place the privacy checklist lists, within the policy window recorded as `erased_at` against the deadline, and the test proves each — observer: script — negative: an embedding or a cached answer surviving the erasure, or an erasure after the deadline
8. (full) Elements of one tenant are never returned to another, proven with two tenants and overlapping content; where the store is Postgres the control is an RLS policy — and once an approximate index exists the proof runs again with the production index and parameters, asserting *k* results per tenant with a partition, a partial index or `hnsw.iterative_scan` beside the policy (`../vector-store/` Verify 4; pgvector README, read 2026-10-05) — observer: script — negative: a cross-tenant hit, or a tenant filter that exists only in a `WHERE` clause where the store is Postgres — framework: beats
9. The privacy checklist states whether stored data is anonymised or pseudonymised, where any reversible mapping lives, and the regimes in scope — observer: Martin — negative: a placeholder dictionary beside the index, or "anonymised" claimed for linkable data

**Example commands (Python):** `python3 ingestion_pipeline.py --audit ./corpus --report audit.json`; `python3 ingestion_pipeline.py --demo`; `pytest tests/test_ingestion.py`.

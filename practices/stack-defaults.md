# Stack defaults

This is the hand-written half of a bundle (decision 0004 §3). The other half — which practices apply to each shape — is generated by `scripts/make-bundles.py` from `scripts/applies.py`, so it cannot drift; this file names the **stack** each shape starts with and the **folders to copy on day zero**. Every path here must exist (`scripts/kb-check.sh` [3] checks the links), which is what keeps a bundle from promising files the KB does not have.

**Promised stacks (decision 0005 §4–5).** Python is the reference stack: every practice's reference implementation is Python. PHP/Laravel and PHP/WordPress are supported through `stack-notes/` (no code) and the implementation prompt; a field-tested variant appears after the first real adoption. **TypeScript is not a promised stack** until a field-tested variant exists; a blank TypeScript repo gets the working-style files (stack-free), the guard, and for each capability practice the contract and prompt only. The router marks the difference as `ref untested` / "no field-tested reference yet".

## Shape A — multi-tenant agent SaaS that acts on the world

- **Default stack:** Python 3.12 (or the machine's 3.11+) / FastAPI / PostgreSQL (with row-level security for tenants) / a queue for anything that sends or writes outside — default: a `jobs` table in the same database, worked by a scheduled command, until volume demands a broker; when `retrieval` is planned: **pgvector in the same PostgreSQL**, exact search (no ANN index) on day zero, the s7 manifest's `index: flat` recording it — an HNSW index, list partitioning by tenant and any dedicated engine are first-user decisions through `vector-store/store-selection.md` (added 2026-10-05, s8). Confirmed by one real instance (AI SDR, 2026-09-28) and one bootstrap (2026-10-01, `sources/2026-10-01-field-report-shape-a-bootstrap.md`, 23 minutes, 13 practices).
- **Day-zero copies:** `practices/verification/python-pytest/` + `practices/verification/dry-run-and-approval.md` (`practices/verification/api-hurl/` with the first HTTP endpoint, not before); `practices/context-docs-skeleton/docs/`; `practices/agent-entry-file/AGENTS.md` + `practices/agent-entry-file/CLAUDE.md`; `practices/hooks-and-guards/dot-claude/` with `practices/hooks-and-guards/stack-notes/python.md`; `practices/security-baseline/lefthook.security.yml` + `practices/security-baseline/dependency-policy.md` and, because `acts_on_world`/`multi_tenant`/`personal_data` are planned, `practices/security-baseline/threat-model-agentic.md` + `practices/security-baseline/mcp-trust-register.md`; `practices/session-state/PROGRESS.json`; `practices/spec-driven/constitution.md`; `practices/prompt-library/` (all); `practices/llm-api-calls/llm_call_skeleton.py` + `practices/llm-api-calls/system-prompt-template.md`; `practices/agent-patterns/tool-definition-template.md` when `exposes_tools` or `tools` is planned.
- **First-user additions** (not on day zero): `practices/llm-gateway/`, `practices/security-baseline/injection-fixture.md`, `practices/token-savings/`.

## Shape B — scheduled LLM publishing pipeline

- **Default stack:** Python 3.12 (or the machine's 3.11+ — record the real version in `docs/stack.md`) scripts or a small FastAPI service / cron or a scheduler / PostgreSQL or SQLite; publishing targets reached through their HTTP APIs (WordPress REST); when `retrieval` is planned: pgvector in the same PostgreSQL with exact search on day zero (`index: flat` in the s7 manifest); when the repo is on SQLite, exact search in the application over a vectors table (or `sqlite-vec` behind the same `Backend`) until the corpus asks for Postgres and pgvector; an approximate index or a dedicated engine only through `vector-store/store-selection.md` (added 2026-10-05, s8). One real instance (Content Central); one bootstrap passed (2026-10-01, `sources/2026-10-01-field-report-shape-b-bootstrap.md`, 13 minutes).
- **Day-zero copies:** `practices/verification/python-pytest/` + `practices/verification/dry-run-and-approval.md` (the dry-run switch is the first file: a publisher without it cannot be tested); `practices/context-docs-skeleton/docs/`; `practices/agent-entry-file/`; `practices/hooks-and-guards/dot-claude/` with `practices/hooks-and-guards/stack-notes/python.md`; `practices/security-baseline/lefthook.security.yml` + `practices/security-baseline/dependency-policy.md` **and**, because `acts_on_world` is planned, the full part: `practices/security-baseline/threat-model-agentic.md` + `practices/security-baseline/mcp-trust-register.md` (the router prints `security-baseline (full)` for this shape); `practices/spec-driven/constitution.md`; `practices/prompt-library/`; `practices/llm-api-calls/llm_call_skeleton.py` + `practices/llm-api-calls/system-prompt-template.md`. Expect `llm-api-calls` assertion 3 (prompt caching) to be n.a. on day zero: a one-prompt rewrite is a few hundred static tokens, under the cacheable minimum.
- **First-user additions:** `practices/llm-gateway/` (fallback and timeouts for a job that must not stall), `practices/token-savings/`, `practices/security-baseline/injection-fixture.md` (needs an eval runner).

## Shape C — content or marketing site with no LLM at runtime

- **Default stack:** PHP / WordPress on the existing fleet tooling (WP-CLI, staging site). No Python in the product; the guard still needs Python on the developer's machine.
- **Day-zero copies:** `practices/verification/web-playwright/` + `practices/verification/cli-bats/` (WP-CLI checks) with `practices/verification/stack-notes/php-laravel.md` as the nearest PHP note until a WordPress one exists; `practices/context-docs-skeleton/docs/`; `practices/agent-entry-file/`; `practices/hooks-and-guards/dot-claude/` with `practices/hooks-and-guards/stack-notes/php-wordpress.md`; `practices/security-baseline/lefthook.security.yml` + `practices/security-baseline/dependency-policy.md`; `practices/spec-driven/constitution.md`; `practices/prompt-library/`.
- **Never:** `practices/worktrees/` (URLs live in the database — see its Stack-sensitive points); any capability practice.

## Shape D — payments / fintech

- **Default stack:** PHP / Laravel (Martin's multi-tenant app is Laravel) or Python / FastAPI; decide per repo and record it in `docs/stack.md`. Laravel has `stack-notes/php-laravel.md` in `hooks-and-guards`, `verification`, `security-baseline`, `llm-api-calls` and `llm-gateway`; no field-tested variant yet.
- **Day-zero copies:** `practices/verification/api-hurl/` + `practices/verification/dry-run-and-approval.md` (money moves → dry run before anything), with `practices/verification/stack-notes/php-laravel.md`; `practices/context-docs-skeleton/docs/`; `practices/agent-entry-file/`; `practices/hooks-and-guards/dot-claude/` with `practices/hooks-and-guards/stack-notes/php-laravel.md`; the **full** `practices/security-baseline/` (`regulated`, `personal_data`, `multi_tenant` planned) with `practices/security-baseline/stack-notes/php-laravel.md`; `practices/spec-driven/constitution.md`; `practices/prompt-library/`.
- **If an LLM is planned:** `practices/llm-api-calls/` from its contract via the implementation prompt with `practices/llm-api-calls/stack-notes/php-laravel.md` — no PHP file is copied, because none has passed Verify (this is the two-arm experiment of decision 0005 §10). When `retrieval` is planned: pgvector in the same PostgreSQL, exact search on day zero, the s7 manifest's `index: flat` recording it; an HNSW index, list partitioning by tenant or a dedicated engine are first-user decisions through `vector-store/store-selection.md` with `vector-store/stack-notes/php-laravel.md` — no PHP file copied (decision 0005; added 2026-10-05, s8).

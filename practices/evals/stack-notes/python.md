# Stack-notes — Python (the reference stack)

Written 2026-10-01. The reference `eval_harness.py` needs only the standard library and Pydantic (https://docs.pydantic.dev/) for the judge's typed verdict; the judge call goes through the repo's one client module (`../../llm-api-calls/`). Check current versions at adoption.

- **Runner:** `pytest` (https://docs.pytest.org/) wrapping `run_suite()` — one parametrised test per task, `k` trials inside, the test fails on pass^k below the floor and prints the worst case; `-p no:randomly` is irrelevant because each trial already makes its own environment.
- **Tasks as data:** `evals/tasks.jsonl` is the source; a `conftest.py` loads it and parametrises by `id`, so a PM adds a task by adding a line, as Anthropic suggests (2026-01).
- **Judge call:** `_real_judge()` wraps the typed structured call of `../../structured-outputs/structured_call.py` (a `{reasoning, verdict}` schema) so the judge is a `structured()` call with its own route, logged and cost-capped like any other call; temperature 0, the pinned model id from `<<JUDGE_MODEL>>`.
- **Calibration:** `--calibrate` computes TPR, TNR, Cohen's κ and the matrix by hand; `scikit-learn` (https://scikit-learn.org/) is fine for the same numbers if already a dependency, but the record must say which definition of κ it reports.
- **promptfoo** (https://www.promptfoo.dev/docs/intro/; CLI and library, YAML test cases, matrix views, caching, CI, red-teaming, runs locally as read 2026-10-01) fits as a *runner and matrix view* across prompts and models; its model-graded assertions are someone else's judge prompt — use `python` assertions that call your own graders, or keep them for exploration only.
- **DeepEval** (https://deepeval.com/docs/getting-started; a pytest plugin, `deepeval test run`, as read 2026-10-01) fits as a *runner and tracing* layer; its `GEval` returns a 0–1 score with `threshold=0.5` by default — map the score to a verdict with a threshold you calibrated (assertion 3), or write a custom metric that returns your binary judge's verdict; `JevEval` (the Jev decision model as a grader, "no LLM key needed") is parked with the s4 re-evaluation of Jev after 2026-12.
- **Datastore:** Langfuse (https://langfuse.com/) or LangSmith (https://www.langchain.com/langsmith) hold traces, test sets, prompts and scores — Lucas uses Langfuse "as a database" and its MCP server from Claude Code (2026-07); keep the calibration record and the judge prompts in the repo, not only in the tool.
- **Production sample:** a scheduled job (cron, Celery beat, APScheduler) pulls yesterday's traces from the datastore at the policy's rate and calls `grade()` with the same judges; append the daily rates to `evals/production-rates.jsonl` so stability is a file, not a memory.
- **Clean environment per trial:** `tmp_path`-style temporary directories, a fresh SQLite or a transaction rolled back per trial; for an agent that touches git, a fresh clone per trial (Anthropic's "git history from previous trials" case).
- **Viewer:** Streamlit (https://streamlit.io/) or Gradio (https://www.gradio.app/) from `annotation-ui-brief.md`; Husain's skills for Claude Code (`write judge prompt`, `validate evaluator`, `create annotator review interface`) exist and are "meant to be customized… ultimately it's somebody else's prompt" (2026-07).
- **Pitfall:** `random` or model sampling inside `make_env()` makes trials non-reproducible — seed per trial and record the seed in the run row.
- **Pitfall:** an `unknown` verdict counted as a pass in a custom aggregation; the reference counts it as not-pass and reports it separately.

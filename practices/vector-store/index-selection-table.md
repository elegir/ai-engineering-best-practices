## 2. The exact-search threshold rule, and the three vendor thresholds with their units

**Rule (principle 18 §3.1):** the walking skeleton runs exact search in the database the repo already has; an approximate index is built only above a recorded vector count that the repo measured — the point where exact search no longer meets the latency budget *including the embedding call* (`tuning-and-capacity.md` §7) on the production hardware. `vector_store.py` refuses an approximate spec whose manifest is under `flat_until` (README Verify 2).

The three vendor statements that justify the rule, each with its own unit — do not mix them:

| Vendor, where (read 2026-10-05) | Statement | Unit |
|---|---|---|
| Qdrant Essentials course | "fewer than 10,000 vectors, brute force is often faster and uses less RAM than building HNSW"; `full_scan_threshold=10000` shown as the default in its configuration blocks | a **vector count** in the course; the filtering guide calls the same default "10 kilobytes" — a **payload size** (digest §4: different units, carried with their unit) |
| Weaviate *Vector indexing* | the dynamic index starts flat and switches to HNSW at a threshold, "by default 10,000" objects, one way | an **object count** per collection or tenant |
| Simon Eskildsen, turbopuffer (AI Council, 2025-05-29) | "a couple of thousand, tens of thousands or hundreds of thousands… keep exhaustively search in memory… as you get into the millions… an approximate… index" | a speaker's **order of magnitude**, in memory |

The repo's `<<FLAT_UNTIL>>` is a count the repo measures; the course's number is where to start looking, not the answer.

## 4. How to read the table

1. Start at the first row. Leave it only when the measured count crosses `<<FLAT_UNTIL>>` or the latency budget breaks with exact search on the production hardware.
2. The index follows the placement (principle 18 §3.3): a graph when vectors and graph fit in RAM; clustered or hybrid when they live on disk or object storage, change constantly or are mostly cold.
3. A row is adopted only through `benchmark-protocol.md`: recall@k against exact search, QPS, p99, memory and build time on the repo's fixture, recorded by `vector_store.py`'s `run_benchmark()`. The size bands above are the vendors' and speakers' orientation, not a measurement of your corpus.
